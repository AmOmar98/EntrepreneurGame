# Agent Operations & Traceability Ledger

This directory is the single source of truth for **Agent-managed monitoring ticks, live hotfixes, deployments, and database operations** across **GitHub (`AmOmar98/EntrepreneurGame`)**, **Vercel (`prj_u3jR0YiNr2WnCFEoG6g1yDShikdH`)**, and **Supabase (`vzzbjxmfkmvqkaqxalhr`)**.

## Directory Structure

| Path | Purpose |
|---|---|
| `ticks/` | Periodic health-watcher snapshots (`TICK-YYYYMMDD-HHMMSSZ.md` and `.json`) generated by `node scripts/agent-ops.mjs tick` and enriched with Supabase MCP checks. |
| `incidents/` | End-to-end traceable records (`INC-YYYYMMDD-HHMMSSZ-<slug>.md`) for every alert escalation, live hotfix, rollback, or schema/operational intervention. |

## Required Traceability Fields per Incident (`incidents/INC-*.md`)

Every code or operational action performed by an agent MUST record:
1. **Incident ID & UTC Timestamp** (`INC-YYYYMMDD-HHMMSSZ-<slug>`)
2. **Trigger & Evidence** (Tick file reference, Vercel deployment UID, HTTP status/latency, or Supabase log/advisor observation)
3. **Classification** (`Tier 1 Auto-Fix` vs `Tier 2 Human-Gated Cardinal/SQL`)
4. **Cardinal Invariants Check** (`R1` score/rank privacy, `R2` warn-only validators, `R3` soft prerequisites + L2 exception)
5. **Git & Deployment Traceability**:
   - Worktree path used (isolated from local working tree)
   - Base commit SHA & Pre-hotfix tag (`pre-hotfix-<id>`)
   - Fix commit SHA (`Incident-Id:` trailer) & GitHub branch/PR
   - Target Vercel Deployment UID (`dpl_...`) and post-deploy verification status
   - Exact 1-line rollback command (`git revert <sha> --no-edit && git push origin main` or `vercel rollback <dpl_uid> --yes`)
