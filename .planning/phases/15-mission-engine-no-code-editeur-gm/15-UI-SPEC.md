## Surfaces Inventory (Phase 15 UI surfaces)

### /admin/events — Event list

- Layout: `.main` full-width, standard GM topbar pattern
- Event list: `.wf-card` table with columns: Nom, Slug, Dates, Statut (is_active pill), Organisation, Actions
- Status pill: active = `.eic-pill--green` "Actif"; inactive = `.eic-pill--rose` "Inactif"; draft = `.eic-pill` (neutral)
- Actions per row: "Voir missions" (link → `/admin/events/[id]/missions`), "Cloner" (`.button`), "Activer" (`.eic-toggle-switch`)
- Create event: `.button.primary` "Créer un event" — opens inline form panel or navigates to `/admin/events/new`
- Inline create form: `.admin-form-grid` 2-column — fields: nom (`.input`), slug (`.input`), org (`.select`), date_debut (date `.input`), date_fin (date `.input`). Wide row for description (`.textarea.wide`). Submit: `.eic-button--primary` "Créer l'event"

### /admin/events/[id]/missions — Mission CRUD + ordering

- Layout: breadcrumb `Admin → Events → {event name}`, then `.main` content
- Mission list: `.stack` of `.mission-card` rows (reuse existing `.mission-card` class from globals.css)
- Each mission card: titre, niveau (`.eic-level-badge`), date programmée, kind pill (`.eic-pill--blue`), ord (number), is_active toggle
- Ordering: up/down arrow buttons (`.button.icon` with lucide `ChevronUp` / `ChevronDown`) — no drag-and-drop (deferred per CONTEXT.md)
- Each mission card has "Éditer" and "Livrables" actions
- Create mission: `.button.primary` "Ajouter une mission" — inline form beneath list
- Mission form fields: titre (`.input`), niveau_id (`.select` populated from levels_v2), kind (`simple`|`moscow`|`multi_url` — `.select`), scheduled_date (date `.input`), ord (number `.input`), is_active (checkbox `.checkbox-row`)

### Deliverable template editor (inline in mission, or nested route /admin/events/[id]/missions/[missionId]/deliverables/[id])

- Template form: `.admin-form-grid` 2-column grid
  - titre (`.input`, full width `.wide`)
  - description (`.textarea.wide`)
  - slug (`.input`) — auto-generated from titre, editable
  - composer_kind: `.select` with options `simple` / `moscow` / `multi_url`
  - template_url: `.input` (https:// URL — enforced by httpsUrl Zod schema)
  - auto_validate: checkbox (`.checkbox-row`)
  - is_bonus: checkbox (`.checkbox-row`)
  - max_score: number `.input` (range 1–200)
  - ord: number `.input`
  - is_active: checkbox (`.checkbox-row`)
  - soft_recommends_before: `.select` (nullable — lists other templates in same event with empty "Aucun" option)
- Rubric builder (criteria label + max rows):
  - Label: `Critères d'évaluation` (`.eyebrow` style)
  - Criterion rows: each row = `.admin-form-grid` 2-column: `label` (`.input`, placeholder "Ex: Clarté du problème") + `max` (number `.input`, 1–100)
  - Add criterion: `.button` "Ajouter un critère" (full width in mobile)
  - Remove criterion: `.button.icon` with lucide `Trash2` — confirms via inline text change only (no modal — removal is soft, data not deleted until save)
  - Min 1 criterion required (validated client-side)
  - validation_rules section: rendered below rubric as read-only info with note "Les règles de validation sont warn-only — severity 'error' non supporté par le moteur" — no input field for severity (R2 enforcement in UI)
- Save: `.eic-button--primary` "Enregistrer le livrable"

### /admin/levels — Program levels CRUD (LEVELS-04)

- Layout: `.main`, section heading "Niveaux du programme"
- Level list: `.stack` of rows — each: ord (drag number), id/label text (`.input` inline edit), action buttons
- Ordering: up/down `.button.icon` buttons (same pattern as missions)
- Add level: `.button.primary` "Ajouter un niveau" — appends row to list
- Delete level: `.button.icon` with lucide `Trash2` — inline confirmation text appears "Confirmer la suppression ?" with `.button` "Oui, supprimer" and `.button` "Annuler" in `.toolbar`
- Edit: inline `.input` directly on row (not a modal)

### Player-side: soft_recommends_before amber hint (R3 CARDINAL)

- Location: deliverable page — rendered inside the existing deliverable drawer / detail area
- Condition: `deliverable.soft_recommends_before` is non-null AND the referenced template is not yet `status='validated'`
- Rendering: `.eic-locked-hint--amber` block (background `--wf-amber-tint`, color `--wf-amber`, border `1px solid #DCC394`, border-radius 8px, padding 10px 12px)
- Copy: "Nous recommandons de compléter [titre du livrable précédent] avant celui-ci." (add key to `lib/i18n.ts`)
- NEVER: `disabled` DOM attribute, `pointer-events: none`, grayed-out button, or any form of click-blocking. The hint is purely advisory.
- Icon: lucide `Info` size 14 at `--wf-amber` color, displayed inline before copy text

**Destructive action patterns (no modal dialogs — inline confirmation only):**
1. Deactivate event: toggle button changes to amber state with inline text "Confirmer la désactivation ?" + "Oui" / "Non" inline buttons below the toggle. After confirm: toggle flips, `.eic-pill--rose` "Inactif".

## Interaction Contracts

### Form pattern (all editor forms)

- All mutations via `app/actions.ts` server actions returning `WorkflowState { ok, message }`
- Form hook: `useActionState(action, initialState)` pattern (see AdminDeliverablesTable as reference)
- Pending state: disable submit button (`disabled={pending}`) + button text changes to "Enregistrement…" / "Clonage…"
- Success feedback: `.form-status` panel (blue tint, `.form-status` class) rendered below submit button — displayed for 3s then fades (or stays until next interaction)
- Error feedback: same `.form-status` with `.wf-rose-tint` background + `.wf-rose` color (reuse `.form-error` class from globals.css)
- `revalidatePath` called on all affected routes after mutation — page re-renders with fresh data

### Clone flow (ENGINE-03)

- Single `.button` "Cloner cet event" in event list row actions
- On click: pending state with button text "Clonage en cours…"
- On success: `state.message` shows `admin_engine_clone_success` copy + link "Voir le clone →" (`/admin/events/[new-id]/missions`)
- Clone copies missions + deliverable_templates + settings with new UUIDs; slugs suffixed with `-clone-[timestamp]`; dates unchanged by default (GM adjusts manually)

### Activate event toggle (ENGINE-03 / TENANT-03)

- `.eic-toggle-switch` pattern (same as AdminDeliverablesTable)
- Activating an event deactivates all other events for the same org (server-side, not client-side — UI just reflects server state after revalidatePath)
- Active event displays `.eic-pill--green` "Actif" badge; after deactivate → `.eic-pill--rose` "Inactif"

### Order up/down (ENGINE-01 / LEVELS-04)

- `.button.icon` with `ChevronUp` / `ChevronDown` lucide icons
- Top item: ChevronUp disabled (`.eic-button:disabled` at 0.5 opacity)
- Bottom item: ChevronDown disabled
- Each click = server action `reorderMissionFlow` / `reorderLevelFlow` → revalidatePath → list re-renders in new order
- No optimistic update (list is short, round-trip acceptable)

### Rubric builder (ENGINE-02)

- Client component (needs `useFieldArray`-style local state for dynamic criterion rows)
- Criteria stored as `rubric: { criteria: [{ label: string, max: number }] }` JSON on deliverable_template
- Criterion rows managed in React local state; entire rubric submitted as JSON via hidden input or JSON.stringify
- Minimum 1 criterion enforced: "Ajouter un critère" button disabled when pending submit; no removal of last criterion
- `max` field: number input, min=1, max=100, step=1

### ENGINE-07 — Date simulation

- GM-only: query param `?simulate_date=2026-07-14` on any admin page
- When active: amber topbar pill `.eic-topbar__pill--amber` with copy `admin_engine_simulate_date_active`
- `getSimulatedNow()` helper reads from query param (server) or localStorage (client — only for smoke testing)
- No Player-facing UI change

### Demo mode guard

- All editor forms: when `hasSupabaseEnv()` is false, show `.eic-pill--amber` banner `admin_engine_demo_disabled` at top of the form
- Submit buttons remain visible but return `{ ok: false, message: "Mode demo — aucune écriture possible." }` immediately
- Does NOT break existing 15 E2E demo flows (engine routes are new routes, not existing ones)
